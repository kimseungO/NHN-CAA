# Ch.1 Organization & Project — 요약 노트
> NHN Cloud Training: Cloud Architecting 교재 p.5–36 기반 / 시험 도메인: 클라우드 환경 설계 (10%)

## 1. 조직(Organization)

**정의 3요소**
- NHN Cloud 리소스 관리의 **최상위 계층** → 중앙에서 리소스를 계층적으로 관리
- NHN Cloud를 사용하기 위한 관리 → 사용자 계정 관리 및 콘솔 보안 관리
- **비용 청구 단위** → 조직 하위 리소스 확인 및 예산 관리

**생성 요건**
- 개인/사업자 회원 **모두** 생성 가능
- 조직을 생성하는 회원이 그 조직의 **OWNER**
- 회원의 **결제 수단 필수 등록**
- 조직명 + 도메인 정보 관리, **도메인 정보는 고유(unique)**

**삭제 요건** ⭐출제
- **OWNER만** 삭제 가능 (조직의 다른 역할로는 불가)
- 하위 **프로젝트 및 서비스를 모두 삭제**해야 조직 삭제 가능
- 삭제 시 조직의 모든 정보가 삭제되며 **복원 불가**

## 2. 조직 거버넌스 설정 (5종)

| 항목 | 핵심 |
|---|---|
| IP ACL 설정 | 허용 IP/대역에서만 콘솔 접근. 공통 설정(모든 조직 서비스 동일) / 서비스별 설정(Cloud, Online Contact 등) |
| 승인 프로세스 관리 | 설정 시 승인 권한자의 승인 절차를 거침. **지원 서비스: Secure Key Manager**. 기본값 = 설정 안 함 |
| 인스턴스 이름 관리 | Instance명 관리 규칙. **중복 허용** 또는 **Unique 관리** 선택 |
| 리소스 권한 통제 및 접속 단말 제한 | 설정 시 **운영자의 리소스 조회 기능이 제한**됨 |
| 개인정보 보호 설정 | ① 멤버 목록 다운로드 비활성화(허용 IP/대역만 가능) ② CloudTrail 로그 내 개인정보(이메일·이름·ID) 마스킹 |

## 3. IAM 거버넌스 설정

- **로그인 보안**: 공통 설정만 지원 (서비스별 설정 미제공)
- **2차 인증**: 필수/선택 설정. 방식 = **Google OTP**(OTP 앱의 One Time Password) / **이메일·휴대폰**(인증 버튼 클릭 후 인증). 예외 IP 설정 시 해당 IP에서는 2차 인증 없이 로그인 가능
- **로그인 실패 보안**: 지정 횟수 실패 시 입력한 잠금 시간만큼 잠금
- **로그인 세션**: 세션 유지/자동 만료. 만료 후 재로그인 필요
- **비밀번호 정책**
  - 기본: 영문+숫자+특수문자 포함 **8자리 이상**, 대소문자 구분, **4자리 이상 연속/동일 문자·숫자 불가**(1111, 1234, abcd), **90일마다 변경**
  - 사용자 정책: 최소 길이 **8~15자(최대 15)**, 강도, 만료(연장 여부), **재사용 제한 1~3개**, 적용 시점(변경 시 적용 / 즉시 적용)

## 4. 조직 서비스

**CloudTrail** — 콘솔·API 등 조직과 프로젝트에서 발생하는 **이벤트 조회**
- 조직 단위 제공, **별도 활성화 과정 없이 바로 사용 가능 / 비활성화 불가**
- 콘솔에서 **최근 90일** 로그 조회
- **Object Storage에 저장** 가능 (오브젝트 스토리지로 로그를 저장 후 다운로드)
- 조직의 CloudTrail 권한 필요

**Resource Watcher** — 그룹·태그로 조직 내 모든 리소스를 관리
- 조직 단위 제공, **자동 활성화 / 비활성화 불가**
- 리소스를 그룹·태그로 논리적 단위 관리, 변경 사항 감지 후 조건에 따라 **알림 발송**
- 프로젝트·서비스·리전 등 조건으로 빠른 검색

**알림 수신 그룹 관리**
- 조직 생성 시 **기본 알림 수신 그룹** 자동 생성
- 조직의 **OWNER, ADMIN이 기본 포함**
- 알림 방법 = **EMAIL, SMS**

**예산 관리**
- 금액 또는 사용량 지정 → 알림
- 초과 시 **전일 사용량 기준으로 다음 날 오전 10시** 알림
- 임계치 기준일 설정 시 기준일까지 사용량 기준 다음 날 오전 10시 알림
- 알림 대상은 역할 또는 조직 멤버 중 직접 선택

## 5. 프로젝트(Project)

- 서비스와 리소스를 담는 **작업 공간**. 조직 생성이 선행 필수
- **프로젝트를 생성하는 멤버가 그 프로젝트의 ADMIN**
- 하나의 조직에 **여러 개의 프로젝트** 생성 가능 (부서/사업 단위 등)
- 프로젝트 단위로 서비스 카테고리 활성화: Compute, Container, Network, Storage, Database, Hybrid & Private Cloud, Monitoring, Game, Content Delivery, Notification, AI Service, Machine Learning, Application Service, Security, Mobile Service, Search, Data & Analytics, Dev Tools, Management, Bill
- 프로젝트 부가 기능: 알림 수신 그룹 관리, **쿼터 관리**(현재 사용 리소스의 쿼터·사용량 확인 및 조정 신청)

**프로젝트 삭제** ⭐출제
- **조직 Owner, ProjectRole Admin 역할만** 삭제 가능
- 하위에 서비스 및 리소스가 없어야 삭제 가능
- 삭제 시 프로젝트의 **모든 리전 서비스**가 삭제되며 **복원 불가**
- 이용 내역을 즉시 결제해야 삭제 가능, 아니면 다음 결제일에 자동 청구

## 6. NHN Cloud 계정 vs IAM 계정 ⭐핵심 비교

| 구분 | NHN Cloud 계정 | IAM 계정 |
|---|---|---|
| 정의 | NHN Cloud 회원 계정. 서비스 전체에서 유효한 멤버. **소속 조직이 삭제되어도 계정은 존재** | 서비스 이용용. **조직 내에서만 유효**한 멤버. **소속 조직이 삭제되면 함께 삭제** |
| 등록 방법 | 조직의 OWNER/ADMIN이 **NHN Cloud ID를 입력**하여 등록 | 조직의 OWNER/ADMIN이 조직 내 **고유한 ID를 입력**하여 등록. SSO 연동·API 등록도 가능 |
| 역할 | 조직 관리(생성/수정/멤버/서비스/결제), 프로젝트 생성·삭제 | 권한에 따른 조직 및 프로젝트 서비스 이용 |
| 콘솔 접근 | `https://console.nhncloud.com/` + 회원 ID(이메일)/비밀번호, (선택)2차 인증 | `https://{조직도메인}.console.nhncloud.com/` + 조직에서 설정한 고유 ID, (2차 인증·서비스별 설정) 인증 |

- 프로젝트 멤버와 조직 멤버는 **종속되지 않음** → 조직 멤버가 아니어도 프로젝트 멤버가 될 수 있음 (NHN Cloud 계정의 경우)
- 반면 **IAM 계정은 조직에서 생성한 계정만** 프로젝트에서 사용 가능
- 프로젝트 멤버에게 **여러 역할 부여 가능**

## 7. 조직 멤버 역할 권한표 ⭐암기

역할: OWNER / ADMIN / MEMBER / Billing VIEWER / Log VIEWER / BUDGET ADMIN / BUDGET VIEWER / ORG DASHBOARD VIEWER / NONE

| 작업 | 가능한 역할 |
|---|---|
| 조직 생성 / 조직 삭제 | **OWNER만** |
| 조직 설정 | OWNER, ADMIN |
| 조직 멤버 등록·삭제 | OWNER, ADMIN |
| 조직 서비스 활성화·비활성화 | OWNER, ADMIN |
| 청구서 조회 | **OWNER만** |
| 이용 현황 | OWNER, ADMIN, Billing VIEWER |
| 예산 설정 | OWNER, ADMIN, BUDGET ADMIN |
| 예산 조회 | OWNER, ADMIN, Billing VIEWER, BUDGET ADMIN, BUDGET VIEWER |
| 프로젝트 생성 | OWNER, ADMIN, **MEMBER** |
| 프로젝트 삭제 | OWNER, ADMIN |
| 사용자 Action 로그 조회 | OWNER, ADMIN, **Log VIEWER** |
| 조직 대시보드 조회 | **전 역할 가능(NONE 포함)** |

요약 포인트
- OWNER = 계정의 모든 역할 부여 + 서비스 신청, 회원 등록, ADMIN 지정
- MEMBER = **프로젝트 생성만** 가능 (프로젝트 생성 통제가 필요하면 역할 할당 검토)
- Billing VIEWER = 이용 현황 확인 / Log VIEWER = CloudTrail 사용자 로그 조회

## 8. 프로젝트 멤버 역할

**프로젝트 관리 (ProjectRole)**
| 역할 | 권한 | 성격 |
|---|---|---|
| ADMIN | 프로젝트 전체 Create/Read/Update/Delete | "판을 설계하고 생존을 결정하는 설계자" — 생성부터 폐기, 서비스 활성화, 보안·예산(쿼터)까지 전체 통제권 |
| MEMBER | 프로젝트 내 모든 서비스 Create/Read/Update/Delete (프로젝트 관리 제외) | "판 위에서 실질적인 성과를 만드는 실행자" — 허용 서비스 내 리소스 자유 생성·수정 |
| VIEWER | 프로젝트 기본 정보/통합 Appkey/멤버/역할 그룹/알림 수신 그룹/쿼터 Read | "판의 흐름을 읽고 현황을 파악하는 관찰자" — 읽기 전용 상태 점검 |

세부 역할: PROJECT MANAGEMENT ADMIN, PROJECT MEMBER ADMIN, PROJECT NOTICE GROUP MANAGEMENT ADMIN, PROJECT API SECURITY SETTING ADMIN, PROJECT QUOTA MANAGEMENT ADMIN / MARKETPLACE_VIEWER, BILLING VIEWER, PROJECT MANAGEMENT VIEWER 등

**프로젝트 서비스 이용 역할** — 서비스별로 세분화
- ADMIN: 서비스별 전체 권한 (Infrastructure ADMIN, Object Storage ADMIN, RDS for MySQL ADMIN, Secure Key Manager ADMIN …)
- VIEWER: 서비스별 조회 권한 (NHN Container Registry VIEWER, RDS for MySQL VIEWER …)
- PERMISSION: 서비스별 **활성화/비활성화** 권한 (Infrastructure PERMISSION, Object Storage PERMISSION …)

## 9. 역할 그룹 > 역할 > 권한 > 조건 ⭐개념 계층

- **역할 그룹(Role Group)**: 특정 역할 및 개별 권한을 조합하여 구성한 그룹 단위 = **사용자 정의 역할**
  - 예) PROJECT MEMBER ADMIN + PROJECT BILLING VIEWER의 연관 권한 + Project.Payment.Get → 'Group A'
- **역할(Role)**: 서비스 및 기능을 이용하기 위한 역할/권한의 **묶음 단위** = **사전 정의 역할**
  - 예) CloudTrail VIEWER = ORG_DASHBOARD_VIEWER + CloudTrail:EventLog.List + CloudTrail:ExternalStorageConfig.Get
- **권한(Permission)**: 서비스와 기능을 이용하기 위한 **최소 단위**. 형식 = `%서비스명%:%권한명%`
  - 예) Project.Payment.Get, CloudTrail:EventLog.List
- **조건(Condition)**: 시스템 내 접근 제어 등 역할에 부여되는 단위. **역할과 역할 그룹에 부여 가능**
  - 조건 종류: 요청 URL / 브라우저 종류, OS 버전 / 날짜 및 시간 / 요일 / 클라이언트 IP

## 11. 설계 사례 (회사 A)

요구: 인프라 부서가 비용·운영 관리 / 회계팀이 전체 비용 확인 + 사업부별 담당자도 비용 관리 / 보안 담당자가 계정 보안 점검 / 사업부 A는 모바일 앱 보안, 사업부 B는 ML 플랫폼

설계 결론
- 단일 법인 + 사업부별 비용 현황 확인 → **단일 조직 구성 후 사업부별 서비스에 대한 프로젝트를 구성**
- 인프라 부서가 비용·운영 관리 → 조직 **OWNER** 및 프로젝트 **ADMIN**을 시스템 담당자에게 할당
- 회계팀 담당자 → 조직의 **IAM 계정 + Billing VIEWER**, 사업부별 회계 담당자에게도 **Billing VIEWER**
- 각 부서 담당자 → **IAM 계정**으로 각 프로젝트 서비스별 권한 할당 (NHN AppGuard ADMIN, AI EasyMaker ADMIN, Security Advisor ADMIN 등)

## 12. 자주 나오는 함정 포인트

1. 조직 삭제는 **OWNER만** (ADMIN 불가) / 복원 **불가** (예제 2번 오답 유도)
2. 프로젝트 생성은 **MEMBER도 가능**, 프로젝트 삭제는 불가
3. CloudTrail·Resource Watcher는 **비활성화 불가**
4. 조직 대시보드 조회는 **NONE 역할도 가능**
5. IAM 계정은 조직 삭제 시 **함께 삭제**되지만 NHN Cloud 계정은 **남음**
6. 프로젝트 멤버 ≠ 조직 멤버 (종속 관계 아님)
7. 정적 라우트·VPN 게이트웨이 관련 쿼터는 **조정 불가**
8. 예산 알림은 **다음 날 오전 10시** (실시간 아님)
