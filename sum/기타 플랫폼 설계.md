# PART 1. Notification

## 1. Notification 개요

고객 커뮤니케이션에 필요한 다양한 메시지를 **통합한 플랫폼**.

**제공 채널 6종** — Push / Email / SMS(국제 SMS 포함) / RCS / KakaoTalk Bizmessage

**4대 특징**

| 특징 | 내용 |
|---|---|
| 통합 메시징 서비스 제공 | 모든 채널을 하나의 플랫폼에서 |
| 메시지 유형별 독립적인 API 운영 | 채널마다 별도 API |
| **멀티 벤더 구성**을 통한 고가용성 보장 | 단일 벤더 장애에 대응 |
| 모든 서비스 유형에 대한 **자체 개발자 보유** | 외부 마케팅솔루션과 쉬운 연동 |

- API 연동 시 **보안 프로토콜**을 사용하고, 고객 데이터는 **DB에 암호화**하여 보관

## 2. Push

- Android OS / iOS 기기에 **통합 발송**
- 인증서 관리 대상 3종 ⭐: **FCM**(Firebase Cloud Messaging, Google) / **ADM**(Amazon Device Messaging) / **APNS**(Apple Push Notification service)
- 푸시 유형별 **인증서 또는 API Key**를 관리

**주요 기능**

| 기능 | 핵심 |
|---|---|
| 알림/홍보성 필터링 | 정보통신망법(제50조 1~8)에 따라 토큰 등록 시 알림·홍보성·**야간홍보성** 수신 동의 여부를 함께 입력받아 **자동 필터링** |
| 국가 필터링 | 토큰 등록 시 국가 코드 입력 → 발송 시 발송 국가 지정 |
| 공통 메시지 형식 | **언어 코드** 기준으로 작성 → 해당 언어·기기 종류에 맞게 메시지 생성 |
| 광고성 관리 | (광고), 연락처, 수신 철회 방법 등 **광고 표시 문구**를 메시지에 삽입. 삽입 여부는 **언어 코드(ko, ko-KR 등)별로 설정** |
| 예약 발송 | 한 번 / 매일 / 매주 / 매월. **현지 시간**에 맞춘 예약 발송 |
| 메시지 유효기간(TTL) | 유효기간이 지나면 **실패 처리**. **0으로 설정 = 유효기간 없음** → 발송 지연으로 인해 실패 처리되지 않음 ⭐ |
| 피드백 제공 | 삭제되거나 잘못된 토큰은 발송 시 **자동 삭제**, 피드백 API로 삭제 토큰 조회 |
| Public API | 토큰 등록·조회, 메시지 전송, 피드백 확인. **API 탭에서 테스트 가능** |

## 3. SMS ⭐숫자 암기

| 유형 | 용량 |
|---|---|
| SMS | **90 바이트** |
| LMS | **2,000 바이트** |
| MMS | **2,000 바이트 + 이미지** |

- Excel 파일로 수신자 목록 입력 → **대량 발송**
- 예약 발송 / **치환 태그**(수신자별 개별화) / **템플릿** 등록
- 발송 내역 조회 지원

## 4. RCS (Rich Communication Service) ⭐숫자 암기

> 기존 SMS/MMS 대비 다양한 기능을 제공하는 서비스. **자(字) 단위**로 세는 것이 SMS(바이트)와 다름.

| 항목 | 값 |
|---|---|
| SMS | 최대 **100자** |
| LMS / MMS | 최대 **1,300자** |
| MMS 첨부 파일 | 최대 **6개** |

- MMS 유형: **가로 / 세로 / 슬라이드** 형태 발송
- 메시지 발송 시 **액션 버튼** 추가 가능
- **RCS Bizmessage를 수신하지 못하는 단말기 → 기존 SMS 서비스로 대체 발송** ⭐
- 인증된 **사업자등록번호**로 **RCS Biz center**에 등록한 브랜드 정보 연동
- 발송 기능 및 조회 **REST API** 제공

## 5. Email

- Excel 대량 발송 / **태그 발송** / 예약 발송 / 치환 태그 / 템플릿
- **광고 메일 수신 거부 관리** — 수신 거부 목록 조회, 목록에 주소 추가
- **Email 보안 기능 3종** ⭐: **SPF / DKIM / DMARC** 레코드 인증
- 통계 조회(전송 결발 상세 결과 분석), 전송 기능 및 조회 REST API

## 6. KakaoTalk Bizmessage — 알림톡 vs 브랜드 메시지 ⭐⭐핵심 비교표

| 구분 | 알림톡 | 브랜드 메시지 |
|---|---|---|
| **대상** | **모든** 카카오톡 사용자 | **친구를 맺은** 카카오톡 사용자 |
| **메시지 내용** | **정보성**(공지, 알림, 안내) | **광고성**(뉴스레터, 이벤트 쿠폰) |
| **스펙** | [텍스트] 1,000자 / [이미지] 1,000자 / [아이템리스트] **700자** | [텍스트] 1,300자 / [이미지] **400자** / [와이드] **76자** |
| **특징** | **템플릿 검수 완료 후** 발송 | **마케팅 수신동의** 사용자 대상 광고성 발송 |

**알림톡 추가 포인트**
- **휴대폰 번호 기반** → 친구 추가와 관계없이 발송
- SMS보다 저렴한 비용으로 **1,000자까지 장문** 발송
- 유형: 텍스트형, 이미지형, 강조 표기형, **아이템 리스트형**
- **카카오 인증마크**가 함께 발송 → 브랜드 신뢰도 상승
- **카카오톡을 사용하지 않는 수신자에게는 문자 메시지로 대체 발송** → 높은 도달률 ⭐
- 콘솔에서 발송 테스트, 발송 내역 조회, 템플릿 관리

**브랜드 메시지 추가 포인트**
- 광고주(고객사)의 **마케팅 수신 동의(마수동)** 회원 대상 → **채널 친구 여부와 관계없이** 광고성 메시지 발송 가능 ⭐
- 마수동 발송을 위해 발신 채널에 **080 수신거부 정보**를 등록해야 함 ⭐
- 마수동 발송은 **기본형(템플릿)으로만** 가능
- **정보통신망법에 의거 20:50부터 다음 날 08:00까지 발송 제한** ⭐⭐ (야간 광고 발송 제한)
- LMS/MMS보다 저렴한 비용으로 텍스트 및 이미지 첨부 발송
- **브랜드 메시지 발송 실패 시 문자 메시지로 대체 발송 가능**

## 7. Notification Hub

**하나의 API로 6개 메시지 채널** — SMS, 알림톡, 브랜드 메시지, RCS, Email, Push ⭐

- 구성: **통합 콘솔 + 통합 API**

| 기능 | 핵심 |
|---|---|
| 멀티 채널 메시징 | 6개 채널로 발송. 다양한 채널을 하나의 API로 통합 관리 |
| 주소록 | 수신자 연락처(이메일·휴대폰 번호·토큰) 체계적 관리, **그룹 관리**, **수신 거부 내역 관리**로 불필요한 발송 방지 |
| 템플릿 | 모든 메시지 채널의 템플릿 등록·관리 |
| **플로우** ⭐ | 사전 등록한 템플릿으로 플로우 생성. **최대 6개** 메시지 채널로 동시 발송 가능. **단말기 상태로 인해 수신 실패 시 사전 설정한 발송 순서에 따라 다음 순서 채널로 자동 발송** |
| 대량 발송 | 수신자 그룹을 **OR/AND 조건**으로 조합해 타기팅 (예: 30대 AND 서울 AND 기혼). Excel 수신자 파일 업로드 시 **유효/무효 수신자 구분** |

# PART 2. AI Services & ML

## 8. AI / ML / DL / GenAI 개념 계층

포함 관계: **AI ⊃ ML ⊃ DL ⊃ GenAI**

| 용어 | 핵심 | 하위 분류 |
|---|---|---|
| 인공지능(AI) | 인간의 지능을 기계로 구현. 가장 넓은 연구 분야 | **강한 인공지능(Strong AI)** / **약한 인공지능(Weak AI)** — 현재 실용 서비스는 대부분 약한 AI |
| 머신 러닝(ML) | 컴퓨터가 **데이터를 통해 스스로 규칙(학습)**을 찾음 | **지도 학습(Supervised)** / **비지도 학습(Unsupervised)** / **강화 학습(Reinforcement)** |
| 딥 러닝(DL) | 인간의 뇌 구조를 모사한 **인공 신경망(ANN)**을 다층으로 쌓음. **대규모 데이터**를 처리할수록 성능 향상 | 이미지 인식, 자연어 처리 등 비정형 데이터에 강점 |
| 생성형 AI(GenAI) | 학습 데이터를 바탕으로 인간이 원하는 **새로운 콘텐츠 생성**(텍스트, 이미지, 코드) | 분류·예측을 넘어 창조 |

> 핵심 대비: 기존 프로그래밍 = **사람이 만든 규칙**에 의존 / 머신 러닝 = **데이터가 만든 모델**을 통해 서비스 구현

## 9. NHN Cloud AI/ML 3계층 스택 ⭐암기

| 계층 | 포함 서비스 | 성격 |
|---|---|---|
| **AI Services – Easy to Use** | Face Recognition, OCR, Text to Speech, Speech to Text | 이미 학습된 AI 모델을 **API 형태로 제공**. 별도 ML 모델 구축 없이 사용 |
| **ML Platform – Easy ML Setup** | **AI EasyMaker**, **Deep Learning Instance** | ML 모델 **개발·학습·배포**를 쉽게 하는 플랫폼 |
| **AI/ML Infrastructure – Build your Space** | **GPU Instance**, Object Storage, Block Storage, NAS | 고성능 GPU 인스턴스 + 대용량 데이터 저장 스토리지 |

## 10. GPU Instance ⭐⭐숫자 암기 (함정 다발)

| GPU | 아키텍처 | 최대 GPU 수 | TFLOPS | 특징 |
|---|---|---|---|---|
| **V100** | Volta | **8개** | **125** | 학습용 고성능 GPU의 **시초** |
| **T4** | Turing | **12개** ⭐예외 | **65** | **추론 효율 및 가성비** 중심 |
| **A100** | Ampere | 8개 | **624** | 전력 효율적 성능, **범용성** |
| **H100** | Hopper | 8개 | **1,979** | **LLM 학습의 현재 표준** |
| **B200** | Blackwell | 8개 | **4,500** | **추론 효율 극대화** |

- **T4만 최대 12개**, 나머지는 모두 최대 8개 ⭐대표 함정
- 제공 GPU는 **NVIDIA** 계열. 향후 **국산 반도체 등 타 벤더 모델**도 출시 예정
- [참고] **AI EasyMaker, NKS, NCS**를 사용하여 **관리형 GPU 컨테이너** 사용 가능 ⭐

**함께 쓰는 스토리지**

| 스토리지 | 용도 |
|---|---|
| Object Storage | **탄력적 용량 + 높은 내구성**. 대용량 **학습 데이터 세트** 저장·관리에 용이 |
| Block Storage | **SSD 옵션** 선택 시 빠른 액세스와 **I/O 병목 현상 방지** (고성능 IOPS 필요 시) |
| NAS | **GPU 클러스터 환경**에서 여러 노드가 **데이터 공유** |

## 11. AI EasyMaker — 파이프라인 ⭐⭐

**개발(노트북) → 학습(Training) → 모델 관리 → 엔드포인트(Serving)**

### 노트북 (개발)
- 머신러닝 개발을 위한 **필수 패키지가 설치된 Jupyter 노트북** 제공
- TensorFlow, PyTorch 프레임워크 환경, AI EasyMaker 기능을 사용할 수 있는 **SDK** 포함
- **CPU / GPU 인스턴스 타입 선택** 가능
- **노트북 중지 후에도 인스턴스 타입 변경 가능** ⭐
- OS 이미지: TF/PyTorch가 **설치된 이미지** 또는 **설치되지 않은 Python 이미지** 선택
- **부트 스토리지 / 데이터 스토리지 크기 지정** 가능, **NHN Cloud NAS를 네트워크로 연결** 가능 ⭐
- 노트북 열기 → 브라우저 **새 창**. **콘솔에 로그인한 사용자만 접근 가능** ⭐
- 상태가 **ACTIVE인데도 접근 불가**하면 **재부팅** 가능
- **삭제 작업은 취소할 수 없음** ⭐

### 학습 (Training)
- 인스턴스 타입 + OS 이미지 선택 → 알고리즘 정보 + **입력/출력 데이터 경로** 입력
- **학습 템플릿** 사용 또는 새로 생성
- **최대 10개 노드 분산 학습** 가능 ⭐숫자
- 학습 결과 지표는 **텐서보드(TensorBoard)**로 확인·분석 ⭐
- 하나의 알고리즘을 여러 번 학습하여 정확도를 높이고, **실험(Experiment) 단위로 그룹화**하여 비교 분석
- **NHN Cloud 제공 알고리즘** 또는 **사용자 작성 알고리즘** 모두 사용 가능
- 이미지 데이터 처리에 필요한 알고리즘은 AI EasyMaker의 **기본 알고리즘** 활용
- **학습 복사** 기능 → 기존 학습과 동일한 설정으로 새 학습 생성
- **완료된 학습 결과로 모델을 생성**

### 하이퍼파라미터 튜닝 (Hyperparameter Tuning)
- 최적의 하이퍼파라미터 조합을 찾기 위한 튜닝 작업
- 튜닝 설정에 의해 **학습이 반복 실행**되어 목표 성능에 도달한 모델을 생성

### 모델 (Model)
- **학습 결과 모델**이나 **외부 모델**을 **아티팩트**로 관리
- **프레임워크가 PyTorch인 경우, PyTorch 모델 이름과 동일하게 입력해야 함** ⭐⭐함정
- 모델 아티팩트가 저장된 **오브젝트 스토리지 경로** 입력 ⭐
- 선택한 모델을 서빙할 **엔드포인트를 바로 생성** 가능

### 엔드포인트 (Serving)
- **NHN Cloud API Gateway 서비스를 통해** API 엔드포인트를 생성하고 API를 관리
- **엔드포인트 기능을 이용하려면 API Gateway 서비스를 반드시 활성화해야 함** ⭐⭐핵심 제약
- 신규 엔드포인트 생성 시 추가되는 스테이지는 **기본 스테이지**로 설정됨
- **모델이 없을 경우 먼저 모델을 생성해야 함** ⭐(순서 문제 출제)
- API Gateway **리소스 경로**와 리소스의 **파드 수** 입력
- 인스턴스 타입과 수 지정 → 리소스 사용량 정책에 따라 **오토스케일러** 설정
- **새로운 테스트 스테이지로 추가 → 테스트 완료 후 기본 스테이지로 변경** → 기존 도메인으로 바로 적용 ⭐무중단 배포 패턴
- **배치 추론**: AI EasyMaker 모델로 배치 추론 수행, 결과를 통계로 확인. 인스턴스·OS 이미지 선택 + 추론 입출력 데이터 경로 입력

### 개인 이미지 (Private Image)

### Text to Speech (TTS) ⭐숫자
- **지원 언어 4종: 한국어, 영어, 일본어, 중국어**
- 세부 설정: **음성 종류**(남성/여성), **음성 감정**(기본/어두운/밝은), **높낮이**(어조), **속도**(1~2배속 등), **음량**
- 다운로드 파일: **.wav / .mp3**
- **텍스트는 공백 포함 최대 1,000자** 입력 가능 ⭐
- 음성 품질을 위해 **1문장당 200자 이내** 입력 권장 ⭐
- **지원 언어, 숫자, 문장 부호 외**의 텍스트 입력 시 **합성 결과에서 제외**

### Speech to Text (STT) ⭐⭐숫자·제약 다발
- **한국어 음성만 지원** ⭐⭐ (음성 인식은 한국어에 한해 합성 결과 제공)
- 입력 방식: **음성 파일 업로드** 또는 **마이크로 녹음**
- **지원 형식: WAV, WebM, MP3, OGG, FLAC, AAC, AC3** (7종)
- **최대 용량: 3MB**
- **인식 가능 시간: 최소 0.36초 ~ 최대 60초** ⭐
- **권장 사항**: 파일 형식 **WAV** / 비트 **16bit** / 샘플 레이트 **16kHz** / 채널 수 **모노(mono)** / 음성 파일 시간 **10초**
- 최대한 **조용한 환경**에서 녹음 권장
- 결과 다운로드: **JSON, TXT** (인식 결과 파일을 다운로드하여 수정 가능)

## 14. Cloud Computing 책임공유모델 (Shared Responsibility Model) ⭐⭐

| 사용자 책임 (Customer Responsibility) | NHN Cloud 책임 (CSP Responsibility) |
|---|---|
| **데이터·콘텐츠 보안** — 생성·저장·처리되는 모든 데이터 보호, 암호화 | **클라우드 서비스 운영** — Compute, Storage, Network 등 IaaS/PaaS 제공 |
| **애플리케이션 및 플랫폼 운영** — 앱 설정, 구성, 업데이트 및 패치 관리 | **가용 인프라 제공** — 가용성 영역(AZ), 가상 네트워크 품질 보장 |
| **계정 및 권한(IAM)** — 접근제어, 권한 정책, 계정 라이프사이클 관리 | **데이터센터 운영** — 공조, 전력, 상면, 내진 설계 등 물리적 관리 |
| **운영체계 및 네트워크 구성** — OS 패치, Security Groups, 서브넷 정책 | **보안 인프라 유지** — 하이퍼바이저, 물리 서버 무결성 유지 |
| **클라이언트 & 트래픽 보호** — 단말 인증, 데이터 암호화(TLS/SSL) | **전원 안정화** — 무정전 전원 공급(UPS), 이중화, 발전 설비 |

**핵심 원리** ⭐
- **IaaS → PaaS → SaaS로 갈수록 사용자 책임 영역이 줄고 CSP 책임이 커진다.** 반대로 **IaaS는 사용자 책임 영역이 가장 넓다.**
- **Subnet처럼 사용자가 구성 방식을 직접 선택하는 리소스는 사용자 책임 영역** ⭐ (NHN Cloud 영역이 아님)
- 사용자가 접근할 수 없는 영역(하이퍼바이저, 물리 서버, 데이터센터)에 대한 보안은 CSP 책임

**운영 선택지** — **Self-Service**(직접 콘솔 관리) / **MSP 운영**(전문 파트너 위탁, Managed Service Provider)
**NHN Cloud 특징** — 국내외 보안 인증(ISO, ISMS-P 등), 교육 프로그램(전문 교육 제공)

## 17. 취약성 점검

### Server Security Check
- **OS 보안 설정 취약점**을 자동 점검. NHN Cloud 인스턴스 **및 외부 서버** 대상
- **에이전트(Agent)** 방식 — 실행에 필요한 **스크립트는 콘솔에서 제공** → 대상 서버 터미널에서 **관리자 권한**으로 실행
- **Service Gateway와 연계하면 Floating IP를 사용하지 않고도 VPC 내 프라이빗 네트워크 안에 있는 인스턴스에 대한 취약성 점검이 가능** ⭐⭐핵심
- 점검 결과는 **콘솔에서 확인**

| 항목 | 내용 |
|---|---|
| 지원 OS | **Linux 계열(CentOS, Ubuntu 등)**, **Windows 서버** |
| NHN Cloud 인스턴스 | 내부 네트워크를 통해 점검 (필요 시 **Service Gateway 연동**) |
| 외부 서버 | **인터넷 통신이 가능한 환경**이면 NHN Cloud 외부의 **물리 서버·타사 클라우드 서버**도 점검 가능 |
| 네트워크 구성 | 보안 정책상 **외부망 차단** 시 **Service Gateway**를 통해 내부망 환경에서도 안전하게 점검 |

- 점검 종류: **OS 보안 점검**(시스템 전반 보안 설정값 진단) / **사용자 정의 점검**(특정 요건에 맞춘 선택적 점검 항목 구성, 지원 범위 확인 필요)
- 실시간 결과 리포트: **'양호' / '취약'** 상태를 가시적으로 확인
- **결과 요약 API**: Public API를 통해 점검 결과를 **외부 대시보드나 관제 시스템과 연동**
- 점검 이력 관리로 보안 수준의 변화 추이 모니터링
- 활용 시나리오: 서비스 오픈 전 최종 보안 검토 / 월간·분기별 정기 점검 / **ISMS, ISO27001 인증 심사 대응 증적 확보**

### App Security Check
- **웹 및 모바일 애플리케이션**의 보안 취약점 점검
- **수동 검수 + 자동 검수** 제공 (체크리스트 기반 수동 검수 + 분석 툴 자동 검수)
- **사전 질의서**를 통해 서비스 특성을 고려한 점검 수행
- 서비스 유형(**WEB, Mobile**)별 검수 서비스
- 발견된 취약점에 대한 **근본적인 대응 방법과 샘플 코드** 제공
- 프로세스: **[신청자 영역]** 서비스 신청 → Web/mobile Application → 대상 정보 입력 → 신청 완료 / **[검수자 영역]** 검수자 할당 → 보안 검수 수행 → 결과 등록 → 완료

### Webshell Threat Detector
- 인스턴스에 존재하는 **웹 셸을 점검**하고, **실시간 통신이 일어나는 웹 셸을 탐지**
- 웹 셸 탐지를 위해 **OS에 에이전트 설치**
- 의심 행위 발생 시 **실시간 탐지 + 설정된 이메일 주소로 알림 전송** ⭐
- 콘솔 화면에서 웹 셸 이벤트 탐지 확인
- **점검 대상 2종** ⭐: **파일** — 웹 셸 코드에서 식별 가능한 **패턴** 탐지 / **행위** — **프로세스 호출** 행위 탐지
- 대응 방법: **격리, 삭제**

### NHN AppGuard ⭐숫자
- **모바일 앱**의 다양한 보안 위협으로부터 안전한 실행 환경 보장
- 앱 **변조 시도 탐지 및 방어**, 이미 시도된 공격은 **자동 차단**, **블랙리스트** 기능을 통한 통제/관리
- **SO 파일의 변조, 에뮬레이터 탐지**
- **코드 난독화(Code Obfuscation)** 및 **코드 가상화** → 리버스 엔지니어링 방지
  - 난독화: 앱 내 소스코드를 무단으로 추출·분석하는 것을 방지
  - 가상화: 프로그램의 코드를 **가상의 중간 언어**로 변환
- 웹 콘솔 환경뿐 아니라 **개발자 사용에 용이한 CLI 환경 동시 제공** ⭐
- **단말기 리소스 점유율 최소화 — 메모리 약 2MB 추가 점유, 30초 단위 약 10% CPU 사용** ⭐숫자

  - **RDS에 대한 접근 설정**을 점검하여 불필요한 접근을 차단
  - **주기적 자동 점검** 기능 제공, 결과를 **이메일로 전송**

## 21. 암호화 및 인증 — Secure Key Manager (SKM)

**데이터 관리 3종** ⭐

| 유형 | 용도 | 예시 |
|---|---|---|
| **기밀 데이터** | 노출되면 안 되는 데이터 관리 | **접속 정보, 앱 키** |
| **대칭 키** | 데이터 **암/복호화** | **스토리지 암호화** |
| **비대칭 키** | 데이터 **서명/검증** | **데이터 위변조 검증** |

**접근 제어 3종** ⭐: **IPv4 주소 인증 / MAC 주소 인증 / 클라이언트 인증서 인증**

**승인 기능**
- 키 생성, 수정, 삭제 및 접근 통제에 대한 **책임자의 승인 절차**
- **국내·외 보안 인증 심사(ISMS-P, ISO 등)에서 요구하는 키 관리 요구 사항 충족** ⭐

**[참고] SKM이 필요한 서비스** ⭐⭐
- **Encrypted HDD/SSD**, **Object Storage의 컨테이너 암호화**, **DataFlow 서비스의 암호화 필드**(Cipher를 사용하기 위해)는 SKM 서비스가 필요
- (Ch.1 연계) **NAS 생성 시 암호화 설정**에도 SKM 키 저장소 필요, **승인 프로세스 관리**의 지원 서비스도 SKM

**봉투 암호화 (Envelope Encryption)** ⭐
- 암호화 대상 데이터를 암호화할 때 **사용한 암호키(로컬 암호키)만** 외부의 다른 암호키로 보호하는 처리 방식
- 데이터는 애플리케이션에서 자체적으로 암호화·보관 / **로컬 암호키는 SKM API로 암호화하여 보관**
- 복호화 필요 시 **암호화된 로컬 암호키를 SKM API로 복호화**하여 데이터 복호화에 사용
- 배경: 모든 데이터를 SKM API로 직접 암/복호화하면 **성능 및 비용 문제** 발생 → 봉투 암호화가 일반적 해결책

**데이터베이스 접속 정보 관리 활용**
- 기밀 데이터 관리 기능으로 DB 접속 정보를 중앙 집중 관리 → 애플리케이션 서버가 늘어나도 **재배포 불필요**
- 접속 정보 변경 시 **애플리케이션 수정 없이 SKM에서만 갱신**

## 22. 보안 관제 서비스

### Basic Security ⭐⭐무료
- **NHN Cloud 한국 리전을 이용하는 모든 고객에게 제공하는 무료 보안 서비스** ⭐
- **NHN Cloud 자체 애플리케이션 보호**를 위해 수집되고 있는 주요 보안 취약점을 **고객에게 공지**

- 심각한 보안 침해 사고 발생 시 식별된 취약점을 즉각 조치할 수 있도록 지원
- ⚠ **사용자 맞춤형 제공 서비스가 아니므로, 사용자 맞춤형 관제가 필요할 경우 Security Monitoring 서비스를 이용** ⭐⭐대표 함정
- Microsoft Windows OS, Apache 등 범용 애플리케이션의 주요 보안 취약점과 조치 방안 공지

### 보안 관제 특장점 (NHN Cloud SOC)
- **NHN Cloud SOC (Security Operation AI Center)** 중심 — AI 기술과 보안 전문가의 분석 역량 결합
- **AI 기반 위협 탐지 및 자동 분석**: AI 기반 탐지(머신러닝 알고리즘으로 정상 패턴에서 벗어난 비정상 행위 탐지) + **SOAR**(Security Orchestration, Automation and Response — 반복되는 보안 이벤트 자동화)
- **24/7/365 실시간 관제 및 초동 대응**
- **CERT (Computer Emergency Response Team)** — 침해 사고 분석 및 포렌식, 공격 경로 추적, 원인 분석 및 재발 방지
- **지속적인 위협 헌팅 (Threat Hunting)** — 이미 침투했거나 모르는 잠재적 위협 사전 발견
- **SIEM** — 다양한 보안 장비(**WAF, IPS, Firewall** 등)의 로그를 통합 수집하고 **상관관계 분석**
- **CORE AI STACK**: AI Detection, SOAR, SIEM, Machine Learning
- **INFRASTRUCTURE SECURITY**: WAF, IPS/IDS, Anti-DDoS, FW
- **보안 운영 프로세스 4단계** ⭐순서: **수집 및 탐지**(모든 로그를 SIEM으로 수집·실시간 분석) → **분석 및 판단**(**True Positive / False Positive** 판별) → **대응 및 차단**(공격 IP 차단, 보안 정책 강화) → **보고 및 예방**(월간 운영 리포트, 주기적 취약점 점검)

> 24x365 실시간으로 사이버 위협에 대한 감시 및 대응 업무 수행

## 23. 네트워크 보안

### DDoS Guard — Basic vs Managed ⭐

| 구분 | Basic | Managed |
|---|---|---|
| 대상 | **NHN Cloud 인프라 리소스 보호**를 위해 클라우드 내 서비스를 보호 | **고객 맞춤형 구독 서비스** |
| 비용 | **고객에게 무료로 제공** ⭐ | 유료 구독 |
| 기능 | 클라우드 유입 트래픽 **실시간 모니터링**, 내부 리소스 보호를 위한 DDoS 공격 대응 | **서비스 특성별 트래픽 학습 및 임계치 기반 정책 관리와 유효성 검증**, 애플리케이션 **계층(L7) 공격 방어**, **보안 관제팀의 24시간 365일 모니터링 및 상황 전파**, **일간/월간 보고서**, DDoS **상세 공격 정보 전파** |

### WEB Firewall (L7)
- **웹 애플리케이션에 특화된 공격**을 탐지하고 차단 — **SQL Injection, Cross-Site Scripting(XSS)** 등
- **OWASP Top 10, 국정원 8대 취약점**에 대응 ⭐⭐
- **GS인증, PCI-DSS 인증, CC 인증** 획득 ⭐
- **Self 서비스**: 고객이 직접 웹 방화벽을 구축·운영할 수 있도록 **웹 방화벽 이미지 및 운영 가이드 제공**
- **Managed 서비스**: 전문 엔지니어 컨설팅을 통한 설치 및 트래픽 분석을 통한 **정책 최적화 및 운영 대행**, **24시간 365일 보안 관제**를 통해 보안 사고 발생 시 신속 대응, 주기적 패치 및 패턴 업데이트
- 웹 방화벽이 **고객 클라우드 영역에 단독으로 구성**되어 **독립적인 운영 환경과 보안성 보장** ⭐

### Network Firewall (L3/L4)
- NHN Cloud에서 사용하는 **인프라 자산을 보호**하는 네트워크 보안 서비스. **별도의 방화벽 제품 없이** 간편하게 사용
- **안정성을 위해 이중화 구성** ⭐
- **Stateful 방식으로 하나의 정책으로 트래픽 제어** ⭐
- **Hub-Spoke 구조**로 VPC 간 **내부 트래픽**과 **인바운드/아웃바운드 트래픽** 제어 ⭐
- 네트워크 차단 및 허용에 대한 **실시간 로그 검색과 백업** 기능 — **Syslog, Object Storage, Log & Crash Search** ⭐
- 인터넷 환경에서 **사이트 간 암호화된 터널**을 통해 안전한 **가상 사설 네트워크(VPN)** 제공
- **VPC 내부 간 통제는 보안그룹 + Flow Log 구성 권장** ⭐(Network Firewall이 아님)
- ⚠ **[제약]** 한국(판교) 리전의 경우 **신규 네트워크 환경에서만 이용 가능**. 한국(판교) 리전에서 **2022년 3월 7일 이전에 생성한 프로젝트**는 개선 전의 네트워크 환경이므로 **프로젝트를 새로 생성해야 함** ⭐⭐⭐

### 네트워크 보안 3종 비교 ⭐⭐시험 단골

| 항목 | DDoS Guard | Network Firewall | WEB Firewall |
|---|---|---|---|
| **방어 계층** | **L3/L4 (볼륨형)** + Managed는 L7 계층 공격 방어 | **L3/L4** | **L7 (웹 애플리케이션)** |
| **대상 위협** | DoS/DDoS 대량 트래픽 | 인바운드/아웃바운드·VPC 간 트래픽 | SQL Injection, XSS 등 웹 공격 |
| **제어 방식** | 트래픽 임계치·유효성 검증 | **Stateful** 정책 | 웹 요청 패턴·시그니처 |
| **구조** | 클라우드 유입 경로 | **Hub-Spoke, 이중화, VPN 제공** | 고객 클라우드 영역에 **단독 구성** |
| **무료 여부** | **Basic 무료** | 유료 | 유료 |
| **주요 준거** | — | — | **OWASP Top 10 / 국정원 8대 취약점** |

> 계층 판단 팁: **"웹/애플리케이션/HTTP 파라미터" → WEB Firewall**, **"VPC 간·인바운드/아웃바운드·정책 기반 차단" → Network Firewall**, **"대량 트래픽·가용성 고갈" → DDoS Guard**, **"인스턴스 내부 파일·프로세스" → Vaccine / Webshell Threat Detector**

## 24. 자주 나오는 함정 포인트 ⭐⭐

**Notification**
1. **SMS는 바이트(90/2,000), RCS는 자(100/1,300)** — 단위가 다르다. 헷갈리게 출제됨
2. 알림톡 = **모든 카카오톡 사용자 + 정보성**, 브랜드 메시지 = **친구 맺은 사용자 + 광고성**. 단, **브랜드 메시지는 마수동 회원이면 친구 여부와 관계없이 발송 가능**
3. 브랜드 메시지는 **20:50 ~ 익일 08:00 발송 제한**(정보통신망법). 알림톡에는 이 제한 없음
4. Push **TTL을 0으로 설정하면 유효기간 없음** → 발송 지연으로 실패 처리되지 않음 (0 = 즉시 만료 아님)
5. Notification Hub 플로우 = **최대 6개 채널**, 실패 시 **사전 설정한 순서대로 자동 대체 발송**
6. Email 보안은 **SPF/DKIM/DMARC** (SSL/TLS 아님)
**AI/ML**
7. GPU 최대 개수는 **T4만 12개**, V100·A100·H100·B200은 모두 **8개** ⭐대표 함정
8. **GPU 인스턴스는 Auto Scaling을 지원하지 않는다** — CPU 인스턴스와 혼동 유도 (기출 다수 출제)
9. AI EasyMaker **엔드포인트는 API Gateway 서비스 활성화가 필수**. 엔드포인트 생성 전에 **모델이 먼저 존재**해야 함
10. AI EasyMaker 분산 학습은 **최대 10개 노드**
11. 모델 프레임워크가 **PyTorch면 PyTorch 모델 이름과 동일하게** 입력해야 함
12. 노트북은 **중지 후에도 인스턴스 타입 변경 가능**하지만, **삭제는 취소 불가**
13. **STT는 한국어만 지원**, TTS는 **한/영/일/중 4개 언어**. 언어 지원 범위를 뒤집어 출제
14. **STT: 최대 3MB, 0.36초~60초, 권장 WAV/16bit/16kHz/모노/10초** / **TTS: 최대 1,000자, 1문장 200자 권장**
15. Document OCR에서 **사업자등록증만 Excel 다운로드 지원**, 신용카드·신분증은 **JSON만**
16. Face Comparison은 이미지에 여러 얼굴이 있으면 **가장 큰 얼굴**을 기준으로 비교
17. 콘다 환경명 **tf29_py39 = 텐서플로**, **pt112_py39 = 파이토치** (숫자 뒤바꿔 출제)
**Security**
18. 책임공유모델에서 **Subnet 구성, OS 패치, Security Groups, IAM은 사용자 책임**. 하이퍼바이저·물리 서버·데이터센터·UPS는 **NHN Cloud 책임**
19. **IaaS일수록 사용자 책임이 크고, SaaS로 갈수록 CSP 책임이 크다**
20. **Vaccine 두 엔진(AhnLab CPP / Deep Security)은 한 인스턴스에 중복 설치 불가**. **내부망(폐쇄망)은 AhnLab CPP + Service Gateway 연동 필수**
21. **Server Security Check는 Service Gateway 연계 시 Floating IP 없이 프라이빗 인스턴스 점검 가능** — "공인 IP가 필요하다"로 오답 유도
22. **Security Advisor는 한 리전에서 활성화하면 모든 리전에 활성화**되지만, **점검 대상·범위는 리전마다 다르다**
23. **Basic Security는 한국 리전 전 고객 무료**이지만 **맞춤형이 아님** → 맞춤형은 **Security Monitoring**
24. **DDoS Guard Basic은 무료**, Managed는 유료 구독
25. **Network Firewall은 한국(판교) 리전에서 2022년 3월 7일 이전 생성 프로젝트에서는 사용 불가** → 프로젝트를 **새로 생성**해야 함
26. **VPC 내부 간 통제는 Network Firewall이 아니라 보안그룹 + Flow Log 권장**
27. **OWASP Top 10 / 국정원 8대 취약점은 WEB Firewall**의 대응 범위 (Network Firewall 아님)
28. **SKM이 필요한 서비스**: Encrypted HDD/SSD, Object Storage 컨테이너 암호화, DataFlow 암호화 필드, NAS 암호화
29. **봉투 암호화는 데이터가 아니라 "로컬 암호키"를 SKM으로 보호**하는 방식 (모든 데이터를 SKM API로 암호화하는 것이 아님)
30. **SIEM은 보안 솔루션 + CloudTrail 이벤트를 함께 수집**하여 연관 분석
31. **Cloud Access는 제로 트러스트 기반**, 로그 저장은 **Syslog / Object Storage / Log & Crash Search** 3종
32. NHN AppGuard 리소스 점유: **메모리 약 2MB, 30초 단위 약 10% CPU**
